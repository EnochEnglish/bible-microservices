## 1. 项目背景与目标

### 1.1 背景

本项目源于对 AndBible（Android 圣经学习应用）的改造，目标是将其核心功能迁移到 Web 平台，支持本地运行和服务器部署。用户需要一个集多译本阅读、原文研究、注释、灵修、课程学习于一体的在线圣经学习系统。

### 1.2 项目目标

| 目标 | 描述 |
|------|------|
| 多译本阅读 | 支持 22+ 译本（中/英/希腊/希伯来），并排对照 |
| 原文研究 | Strong's 词典 + 形态学标注 + 逐词对照 |
| 学习工具 | 灵修、地图、读经计划、书签笔记 |
| 在线课程 | 门徒训练课程 + 答题系统 + 证书 |
| 知识库 | 多模型语义搜索圣经+图书馆+词典 |
| 轻量部署 | 单体 JAR + Node.js 前端，1GB 内存可运行 |

### 1.3 目标用户

| 用户群体 | 需求 |
|----------|------|
| 个人读经者 | 多译本阅读、读经计划、灵修 |
| 查经/学习小组 | 课程系统、答题、证书 |
| 牧者/教师 | 注释、原文研究、课程管理 |
| 神学院 | 多领域课程、组织管理、证书验证 |

## 3. 功能需求

### 3.1 圣经阅读

#### FR-1.1：多译本阅读

- **需求**：用户可从 22+ 译本中选择阅读
- **输入**：译本下拉框选择
- **输出**：选中译本的经文内容
- **优先级**：P0
- **状态**：✅ 已实现

| 译本类型 | 示例 | 来源 |
|----------|------|------|
| 中文 | cuv_gb（和合本上帝版） | H2 |
| 中文 | ChiUns（新译本） | SWORD |
| 英文 | KJV、WEB、BSB | H2/SWORD |
| 希腊文 | LXX、Byz | SWORD |
| 希伯来文 | OSHB | SWORD |

#### FR-1.2：多译本对照

- **需求**：用户可同时显示多个译本并排对照
- **输入**：选择 2-4 个译本
- **输出**：2 译本左右并排，3+ 译本行式排列
- **优先级**：P0
- **状态**：✅ 已实现

#### FR-1.3：章节导航

- **需求**：用户可快速跳转到指定书卷和章节
- **输入**：书卷选择 + 章节号
- **输出**：对应章节经文
- **优先级**：P0
- **状态**：✅ 已实现

#### FR-1.4：URL 参数直达

- **需求**：通过 URL 参数直接定位经文
- **格式**：`?translation=cuv_gb&book=gal&chapter=3`
- **优先级**：P1
- **状态**：✅ 已实现

#### FR-1.5：TTS 朗读

- **需求**：支持单节和全章语音朗读
- **优先级**：P1
- **状态**：✅ 已实现

### 3.2 逐词对照（Interlinear）

#### FR-2.1：Interlinear 显示

- **需求**：支持 Strong's 标注的译本可显示逐词对照
- **支持译本**：KJV、ChiUns、ChiUn、BSB、OSHB、SP、LXX（共 7 个）
- **优先级**：P0
- **状态**：✅ 已实现

#### FR-2.2：Strong's 编号显示

- **需求**：每个词旁显示 Strong's 编号（H/G 前缀）
- **格式**：H430、G2424
- **优先级**：P0
- **状态**：✅ 已实现

#### FR-2.3：形态学标注

- **需求**：每个词上方显示形态码
- **覆盖**：406+ 形态码
- **悬停**：显示语法解释
- **优先级**：P1
- **状态**：✅ 已实现

### 3.3 Strong's 词典

#### FR-3.1：悬停查询

- **需求**：Interlinear 模式下悬停 Strong's 编号弹出词典条目
- **数据**：希伯来语 8,674 条 + 希腊语 5,667 条
- **优先级**：P0
- **状态**：✅ 已实现

#### FR-3.2：直接搜索

- **需求**：输入 Strong's 编号直接查询
- **格式**：H1-H8674、G1-G5667
- **优先级**：P1
- **状态**：✅ 已实现

### 3.4 经文注释

- **需求**：阅读经文时右侧面板显示注释
- **注释源**：34 个（H2 表 9 源 + SWORD 直读 25 源）

## 5. 用户故事

### US-1：读经

> 作为一名信徒，我想在浏览器中阅读多种译本的圣经，以便对照理解经文含义。

**验收标准**：
1. 可从下拉框选择 22+ 译本
2. 切换译本后自动加载当前章节经文
3. 支持多译本并排对照
4. 支持章节快速导航

### US-2：原文研究

> 作为一名神学生，我想查看原文逐词对照和 Strong's 词典，以便深入理解原文含义。

**验收标准**：
1. Interlinear 模式显示逐词对照
2. 每个词旁有 Strong's 编号
3. 悬停 Strong's 编号弹出词典条目
4. 形态码悬停显示语法解释

### US-3：灵修

> 作为一名信徒，我想每天阅读灵修内容，以便在日常生活中得到属灵喂养。

**验收标准**：
1. 可选择 SME/Daily 灵修来源
2. 日历选择器可查看历史灵修
3. 灵修内容正确分段渲染
4. 经文引用可点击跳转

### US-4：读经计划

> 作为一名信徒，我想按照读经计划每天读经，以便系统性地通读圣经。

**验收标准**：
1. 可从 3 个计划中选择
2. 显示今日应读经文
3. 可打卡标记完成
4. 显示进度百分比

### US-5：课程学习

> 作为一名门徒，我想参加门徒训练课程并完成考试，以便系统性地成长。

**验收标准**：
1. 可浏览课程列表并报名
2. 逐课阅读内容并标记完成
3. 所有课时完成后参加考试
4. 及格后获得证书

### US-6：知识库搜索

> 作为一名查经组长，我想用语义搜索查找经文和书籍内容，以便准备查经材料。

**验收标准**：
1. 输入关键词返回相关结果
2. 可切换搜索模型和模式
3. 结果有关键词高亮
4. 可点击跳转到原文

### US-7：课程管理

> 作为一名教师，我想创建课程和考试，以便教导学生。

**验收标准**：
1. 可创建/编辑课程
2. 可管理章节和课时
3. 可创建考试并自动提取题目
4. 可阅卷主观题

### US-8：模块管理

> 作为一名管理员，我想安装新的圣经译本和注释模块，以便扩展系统功能。

**验收标准**：
1. 可浏览 425 个可用模块
2. 可在线安装模块
3. 安装后模块自动出现在前端
4. 可删除不需要的模块

## 7. 技术约束

### 7.1 技术选型

| 约束 | 原因 |
|------|------|
| Spring Boot 3.x + Kotlin | 现代 JVM 框架，类型安全 |
| H2 文件数据库 | 轻量嵌入式，无需独立数据库服务 |
| JSword | SWORD 模块标准 Java 实现 |
| 原生 HTML/CSS/JS | 无框架依赖，轻量，可控 |
| Node.js 前端服务 | 支持静态文件+API 代理+Zvec |
| nginx 反向代理 | 生产环境标准方案 |

### 7.2 安全约束

- 不在前端存储 openid、session_key 等敏感数据
- JWT token 存储在 localStorage（注意 XSS 风险）
- 所有异步操作有 loading 状态和错误处理
- 验证码防刷（5分钟过期，HMAC 签名）

### 7.3 编码约束

- 前端文件编辑后必须更新版本号
- 中文文件用 Node.js fs.writeFileSync 而非 PowerShell Set-Content（避免 BOM）
- H2 相对路径从 CWD 解析（启动时固定 CWD）
- write 工具覆盖写入，大文件编辑前先备份

### 7.4 i18n 约束

- 双轨制：I18N 对象（JS 动态文本）+ data-zh/data-en 属性（HTML 静态文本）
- topbar 按钮 emoji 移为 HTML 固定前缀，data-zh/data-en 只包裹文本
- 大对象（I18N）编辑后必须 `node --check` 验证语法
